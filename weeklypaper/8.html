SQL 키워드와 역 정규화

Q.

  • SQL에서 DDL과 DML의 차이점을 설명하고, 각각의 대표적인 명령어들의 용도를 설명하세요.
  • 역정규화가 필요한 상황과 적용 시 고려해야 할 사항, 그리고 역정규화를 적용할 때의 장단점을 설명해주세요.

A.

1. SQL에서 DDL과 DML의 차이점을 설명하고, 각각의 대표적인 명령어들의 용도를 설명하세요.
  • DDL : Data Definition Languaga 의 약어. 데이터를 정의 하는 키워드를 말한다.

데이터를 정의 한다는 건 데이터가 어떤 형태인지 정한다는 것 으로, 구체적으론 테이블을 조작하는 것 이다.

CREATE, ALTER, DROP, TRUNCATE 키워드가 포함된다.

  • CREATE : 테이블을 생성하는 키워드.
  • ALTER : 테이블을 수정하는 키워드.
  • DROP : 테이블 자체를 없애는 키워드
  • TRUNCATE : 테이블의 내용을 없애는 키워드

DROP 과 TRUNCATE 의 큰 차이는 테이블이 보존되는가, 테이블 자체도 삭제되는가 의 차이이다. DROP 은 테이블 자체도 지우고, TRUNCATE 는 테이블 내부의 레코드만 지운다.

  • DML : Data Manipulation Languaga 의 약어. 데이터 조작 키워드를 말한다.

테이블에 데이터를 넣거나 빼는 작업을 의미한다.

SELECT, INSERT, UPDATE, DELETE 키워드가 포함된다.

  • SELECT : 레코드를 조회하는 키워드.
  • INSERT : 레코드를 생성하는 키워드.
  • UPDATE : 레코드를 수정하는 키워드.
  • DELETE : 레코드를 삭제하는 키워드.
2. 역정규화가 필요한 상황과 적용 시 고려해야 할 사항, 그리고 역정규화를 적용할 때의 장단점을 설명해주세요.

데이터 베이스를 설계할 때 테이블에서 데이터의 원자성을 정립하고, 테이블의 함수 종속성 을 삭제해 나가면 하나의 도메인을 표현하기 위해 데이터 테이블은 잘게 나누어진다.

이러한 형태는 대부분 쿼리상의 이점으로 다가온다. 삽입, 삭제 수정 시 쿼리 횟수가 줄어들기 때문이다.

다만 테이블이 나뉜 만큼 SELECT 쿼리에서 FROM 연산이 많아지게 된다. 때문에 조회 쿼리의 소요 시간이 늘어나게 된다.

이렇게 조회 시간이 늘어난 경우, 인덱스를 생성하거나 JOIN 을 적절하게 조인하도록 튜닝 하는 등 여러 방법이 있지만, 이마저도 한계가 존재할 때 역정규화를 고려하게 된다.

역정규화는 데이터의 원자성과 종속적 무결성을 저하 한다. 설못 적용한 경우, 데이터 자체가 흔들릴 수 있다. 제약으로 인한 데이터 적용에 문제가 없는지, 원본 데이터와 괴리가 일어나진 않는지 고려 해야 한다.

또한 데이터를 조회 할 때는 속도가 빨라지지만, 테이블 크기가 커진 만큼 수정, 생성, 삭제 작업이 느려진다.

이와 같은 장단점이 상황에 맞는지를 고려해야 성공적인 역 정규화를 진행할 수 있을것이다.
